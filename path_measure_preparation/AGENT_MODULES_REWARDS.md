## 2. 现有奖励值得审计的原因

环境的 `calculate_winloss` 对 1–8 名给 40、35、…、5。`update_dead` 将该名次值与 `player.reward` 相加；非终局回合也会返回 `player.reward`。`player.py` 中的 `won_round`、`loss_round` 会累加或减去战斗伤害值，而在检查的全局搜索中未发现普通全局对局中每回合清零该字段的直接赋值。因此重复返回累计值并求和**可能**重复计入历史战斗贡献；具体 parallel API 是否重复输出仍须对固定轨迹逐步实测，不能仅凭静态阅读断定。

额外风险：代码在 `current_round > 48` 时结束，对所有仍存活者赋予第一名奖励；同时淘汰的排名也要核对。当前不能直接把环境给出的值当作可靠的唯一真实排名标签。需要制定并测试平局规则和回合上限结算规则，保存原始事实，不悄悄修订上游结果。

## 3. 第一版奖励：最终名次

对自然完成、名次已验证的八人局，采用：

`r_t = 0`（非终局），`r_terminal = (8 - placement) / 7`。

第一名为 1，第四名 4/7，第八名为 0。排名奖励以自然终局产生一次，优化器折扣因子第一轮设 `gamma=1`，避免因行动次数或对局长度不同而系统性折损同一名次。具体 PPO/价值训练仍需处理长时序与方差；若后续改 gamma，记为单独实验。对于真正无法确定最终名次的外部超时或异常截断，标为 censored，不赋予虚构终局名次；PPO 是否做 bootstrap 按截断类型分别处理。

这个设计对应期望归一化名次，与最大化前四率或冠军率不完全相同；三种指标均应报告。如后续主要目标明确为前四，可单独评估 `1[placement <= 4]` 奖励，不能与线性排名实验混称。

## 4. 奖励整形：先做消融，不与主奖励混淆

首轮只使用终局名次。若学习过稀疏，可设计可观测状态势函数 `Phi(o)`，按 `r'_t = r_t + alpha * (gamma * Phi(o_{t+1}) - Phi(o_t))` 整形，终止态统一定义 `Phi=0`，外部截断不得伪装为终止。要保证潜在函数状态依赖及终止处理等条件才可讨论策略不变性；部分可观测、多智能体和学习势函数等情况不自动满足这些条件。`Phi` 参数和权重应预先固定或仅用训练/验证集选择，单独汇报原始名次表现与消融。

不把金币、阵容战力、单场胜利等直接硬编码为主奖励：连败攒经济或牺牲血量可能服务于长期排名。它们可先作为诊断变量；若要使用额外奖励须记录公式、权重及可能改变目标的风险。

## 5. Gibbs 样本权重和 RL 奖励的关系

对自然结束、名次可信的第 i 局，定义成本 `C_i = 1 - r_terminal,i`；训练集权重 `p_i = exp(-beta * C_i) / sum_j exp(-beta * C_j)`。`beta=0` 对应均匀权重；记录 beta、全数据集 ESS、最大权重，并在验证集选择 beta。权重用于离线有监督目标：均匀抽样轨迹时，按 `N*p_i` 乘每轨迹 loss 的均值。若抽样单位是窗口，先明确每个 episode 对窗口采样的隐式权重和目标测度。

RL 奖励定义 Agent 希望在环境里获得什么；Gibbs 权重定义离线学习时对已有数据如何重新分配关注。高名次可能来自运气或较弱对手；固定对手池、配对 seed、多训练 seed 和分层统计，以评估在线效果。不要同时按 Gibbs 权重重采样并再次加权 loss。

## 6. 试运行前验收

1. 对完整局逐步记录上游 reward、`player.reward`、回合和终局，实测是否重复计数；验证所有可能终局和平局。
2. 验证 deterministic seed、合法动作 mask、终止/截断和动作前后状态对应关系；人为限步的记录不得当作自然终局。
3. 修好或替换规则基线，至少完成多局，并记录全局上限、对手池和运行时。
4. 为奖励计算做可手算示例：第 1/4/8 名分别为 1、4/7、0；对异常/截断不生成伪名次。用独立数据核验实现。
5. A/B 固定数据、动作 mask、网络、训练量和评估预算；报告平均名次、前四率、冠军率、自然结束率、非法动作率、延迟和 ESS。当前没有正式对局、训练或评估结果。
